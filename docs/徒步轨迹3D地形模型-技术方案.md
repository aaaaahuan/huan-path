## 3. 坐标、比例与高程

### 3.1 投影与边界

输入经纬度按标准 KML 解释为 WGS84，通过 `Transformer.from_crs(4326,32647,always_xy=True)` 转为 UTM 47N 米坐标。未做未经证实的 GCJ 偏移。

按主轨迹 XY 包围框四周各扩展 1,100 m，得到当前 UTM 范围：

```text
xmin = 478683.9896764625
 ymin = 3135247.047408663
xmax = 488281.0895836492
 ymax = 3141576.027944907
```

坐标值来源：`models/validation.json → features.model_extent_utm47n`；扩边规则来源：`build_model.py`。

### 3.2 模型坐标

```text
extent = hi - lo
s = 200 / max(extent)                 # 单位 mm / m
model_xy = (utm_xy - lo) * s
z_base = 4 + (DEM - min(DEM)) * s * 1.25
```

模型左下角为 XY 零点，X 向东、Y 向北、Z 向上，网页与打印均按 mm 解释。当前水平比例 1:47,985.499536、高度夸张 1.25；4.0 mm 配置圆半径约对应地面 191.942 m，仅是纪念符号留白，不是现实建筑用地范围。

模型网格按约 0.32 mm 间距取整，当前 626 × 414，地面样点间距约 15 m；这只是对约 30 m DSM 的插值，不提高真实精度。DEM 范围 1,972.0–4,736.896973 m。轨迹记录海拔与 DEM 中位差 -1.037135 m、绝对差 P90 为 16.937803 m，是当前样本对照，不能代替定位精度测量。

## 4. 建模流水线

### 4.1 轨迹读取与 DEM 重采样

1. KML 从 gx:Track 的 `gx:coord` 按 XML 顺序读取。KMZ 优先读 `doc.kml`，否则只接受单一 KML；包内 KML 有 50,000,000 bytes 上限，不需要将整个包附件解压执行。
2. 当前得到 2,970 点。程序将相邻样点连续处理，跨轨迹段也按顺序连接，没有可靠的自动断段识别；任意 KML 的 LineString 尚不在这条解析路径中。
3. Rasterio 将 `data/dem.tif` 双线性重投影到顶点对齐的 UTM 网格；断言无 NaN。`data/terrain_crop.tif` 保持栅格北向行序，建模数组翻转为南到北。
4. WorldCover 最近邻重采样，避免把类别混成中间数值；写 `data/worldcover_crop.tif`，断言网格无缺失分类值。

### 4.2 地形网格与封底

顶面每个网格单元沿固定对角线拆成三角形；外围按逆时针顺序连接到 z=0 的底边，底面以中心点扇形封闭。建立高度场时就检查封闭、绕序和正体积。此结构是后续可切换地形的固定拓扑。

### 4.3 地表要素

OSM way/relation 组装线与面，relation 外环/内环分别 polygonize 并作差；无效面尝试修复，再与模型边界相交。派生 `data/osm_features_utm47n.geojson` 的坐标单位为 UTM 米，不是普通经纬度 GeoJSON。

| 要素 | 高程与分类处理 | 当前值 |
| --- | --- | --- |
| 河流/溪流 | 线缓冲后栅格化，原 DEM 高程下压；保留沿程坡度 | 宽 1.4 / 1.1 mm，下压 0.45 mm |
| 湖泊 | 多边形内原地形模型高程中位数减槽深，最低水平保护；保留岛洞 | 当前水平 67.890465 mm，检查湖面高差 0 |
| 林区 | WorldCover 树木与 OSM 林地并集，排除水体、雪冰 | 抬升参数 0.32 + 0.12×纹理，实测 0.321471–0.438529 mm |
| 草地 | WorldCover 30，排除高优先级类别 | 浅绿色，无几何抬升 |
| 雪冰 | WorldCover 70 与 OSM glacier 并集，排除水体 | 白色，几何变化 0 mm |

林区纹理是固定正弦组合，不是随机树模型：

```text
texture = 0.5
        + 0.25*sin(2π*x/1.6)*cos(2π*y/1.4)
        + 0.25*sin(2π*(x+y)/2.3)
forest_delta = raise_mm + texture_mm*texture
```

非路线地表类别优先级：水体 > 雪冰 > 林区 > 草地 > 普通地形。禁用某类会恢复普通地形/普通材质，而不是自动露出被高优先级排除的另一类别。单独房屋不再参与高度场抬升；`house_top` 与对应旧缓冲目前保留为全零兼容数据。

### 4.4 路线凸起

主线在模型平面中按不超过约 0.06 mm 步长加密，cKDTree 求每个网格顶点到加密点集的最近距离 `d`。这是密集点近似，不是逐段精确线距。

```text
weight = clip((0.85 - d) / 0.13, 0, 1)
floor = max(base_terrain, feature_surface)
z = feature_surface + weight*(floor - feature_surface + 0.8)
```

`d < 0.72` 为路线核心，边缘渐变至 0.85 mm，形成约 1.7 mm 底宽。保证核心高于原地形与地表较高者约 0.8 mm；面颜色另在三角形质心求线距，以核心阈值赋路线红。房屋断口中 weight 为零且不能赋路线色。

### 4.5 照片解析与网页派生

`import_photos.py` 的源 KML/KMZ 路径目前写死在脚本中；这是本机专用导入工具，不是参数化照片服务。其工作为：

- 找 `标注点` Folder 中 `MarkerStylePicture` 的 Placemark，读取 Point 坐标及 ExtendedData 的 `FileId`、`Time`、`Latitude`、`Longtitude` 等，并校验经纬度一致。
- 按 `FileId ↔ files/pic_<FileId>.png` 关联附件，复制包、KML、doc.kml 和原图，保留 SHA-256。`.png` 后缀附件实际可为 JPEG 编码，按图片实际格式读取，不改源文件。
- 用同一 UTM 范围与比例放置，DEM 双线性取海拔，记录海拔仅作原始字段，不参与高度定位。
- 使用 EXIF 方向纠正后转 RGB，网页大图长边不超过 1,200 px、JPEG quality 85；缩略图不超过 240 px、quality 78，保留原图。
- `Time` 毫秒换算 Asia/Shanghai；不声称已验证 EXIF 拍摄时间。写 `data/photos-2026-01-27/manifest.json` 和 `web/photos/points.json`。

28 点均在范围内，范围外列表为空。照片点锚定 DEM，网页标记可抬高至当前渲染地表与 DEM 锚点中较高者之上，保留连接线和 2.2 mm 标记抬升，避免埋入路线或林区。该抬升不是打印几何。

### 4.7 图钉屋放置、着色与布尔合并

用户选用 `data/house_designs/designs.json` 中 `5_pin_house`：设计约 3.40 × 3.40 × 3.95 mm、200 个三角面、单个封闭体，原点底面中心且 z=0。当前不再修改地形顶点造屋。

1. 读取 STL 焊接拓扑与 GLB 分色部件。代码校验边界和体积一致，以 GLB 面质心最近邻给 STL 三角面匹配白墙或 accent 来源；没有进行通用 Hausdorff 等价检验，替换文件仍需保证同一造型。
2. 按配置筛选点，转换 XY，范围外写入 `outside_indices` 并跳过；本期启用房屋均在范围内。
3. 在路线已留白的地表按网格三角形插值采样中心高程，原点 z=`surface - sink_mm`，按 `scale` 等比缩放，保持 Z-up。
4. 每个放置体与地形求交，要求正交集体积，再用 Manifold 加法批量合并。
5. 若合并出现封闭负体积内腔，填去内腔；正体积组件必须恰好一个。当前填充的内腔体积为 0.000034431128 mm³，不移除断开房屋来冒充单实体。
6. Manifold face provenance 保留原表面材质，屋墙 ID 6、图钉/屋顶/门 ID 7。打印 palette 及网页派生 GLB accent 都用 `#F4A7B9`，白墙 `#F7F7F2`。源 GLB 不改动。

陡坡保持原来的中心贴地与固定下沉，不加台阶、平台或抬高基础；因此部分图钉被山体遮挡。相邻拍摄点放置的图钉可能靠近或相交，打印时自然合并，不做建筑去重。

12 号当前网页原点 `(134.216022, 28.420317, 13.078529)`，屋顶最高中心 `(134.216022, 28.420317, 17.028529)` mm，可作近景观察目标。

### 4.8 4 mm 断口与净距算法

对所有**实际启用并放置**的房屋（true，以及显式包含的 uncertain）计算模型 XY 圆。网格顶点实际遮罩半径为：

```text
route_gap_mm + 2*hypot(grid_dx_mm, grid_dy_mm)
= 4.0 + 0.9041849391234003 mm
```

所有圆取并集。命中的顶点路线 weight 清零，恢复原地表；顶面三角形只要任一顶点在遮罩内，或质心在配置圆内，就禁止路线红色，避免红色边缘跨入房屋区。关闭房屋则忽略保存的 gap 并使用完整路线，打印重建和网页即时切换遵循同一规则。

校验范围是所有“任一顶点有路线抬升”或“面被赋路线红”的地形三角形 XY 投影。计算：

- 房屋中心到这些三角形的最小距离，要求 ≥ 配置半径 4.0 mm。
- 房屋全部设计面投影的并集到这些三角形的最小距离，要求严格 > 0，证明无接触/重叠。
- 中心距离减 `1.7 * scale` 的保守下界，要求 ≥ `min_route_clearance_mm`。当前配置 0.0，另有严格正净距断言，不能把 0.0 理解为允许重叠。

圆内原轨迹长度由逐段线与圆的二次方程交点求参数区间，累加模型平面长度，再除 mm/m 比例得到地面水平长度。这个长度不含渲染宽度与额外网格余量，各圆重叠不能简单求和。

| 房屋编号 | 实际边缘净距 mm | 配置圆内中心线长度 mm | 对应地面水平长度 m |

### 6.1 three.js 场景与材质

`web/vendor/three.module.js` 为本地 three.js r170，配合本地 OrbitControls，无需 CDN。`web/index.html` 创建 Z-up 透视相机、方向光与半球光、地面、MeshStandardMaterial 地形；地形读取索引网格后转为 non-indexed 以实现每面硬分类色。

类别与颜色来自 metadata palette：

| --- | --- | --- |
| 0 | 地形 | `#C6CBB5` |
| 1 | 河流与水体 | `#2389C9` |
| 2 | 林区 | `#24563B` |
| 3 | 冰雪 | `#F5FAFF` |
| 4 | 徒步路线 | `#E94F39` |

照片 sprite 单独使用黄色。图例由当前状态重建，房屋两类材质均受同一 houses 开关控制。

`web/metadata.json` 保存构建事实、有效配置、尺寸、palette、照片摘要、房屋原点与净距、`preview_layers` 描述及校验状态。当前与 `models/validation.json` 内容一致，构建会覆盖它们。

| 文件 | 类型 / 形状 | 含义 |

| `web/faces.bin` | little-endian Uint32，F×3 | 地形索引，顺序为顶面后侧底面 |
| `web/colors.bin` | Float32，N×3 | 初始顶点 RGB；分类面色还会按 face_materials 重建 |
| `web/face_materials.bin` | Uint8，F | 地形默认面类别 ID |
| `web/layers/base_z.bin` | Float32，顶面顶点数 | 原始 DEM 模型高程 |
| `web/layers/classes.bin` | Uint8，顶面顶点数 | 构建时可用地表类别 |
| `web/layers/route_distance.bin` | Float32，顶面顶点数 | 完整路线距离场，恢复路线所需 |
| `web/layers/forest.bin` | Float32，顶面顶点数 | 林区抬升量，禁用时 descriptor 为 null |

| `web/house_designs/5_pin_house.glb` | GLB 2.0 | 当前配置着色的房屋派生资产 |

缓冲为顶点/面定序数据，不含自描述头部；解释须依赖 metadata，不能混用不同构建的文件。当前 vertices 文件 3,134,892 bytes，faces 文件 6,269,736 bytes，均由实际文件大小取得。

### 6.3 元素开关与预览重建

`web/features.js → composePreview` 重算顶点 z 和非路线类别；按保存的完整路线掩膜及当前 houses 状态决定断口。更新地形法线，再转非索引网格重写面颜色。当前刷新会分配新几何并遍历全部面，尚未做增量更新或 LOD。

`state.houses=false` 时忽略 gap，完整路线凸起与红色恢复，同时隐藏 GLB group。切换林区/水体时，用三角形插值重新调整图钉 z 保持相同 sink；照片通过回调刷新可见锚点。构建时未启用的类别按钮标记“未构建”并禁用，不能依靠网页开关补回缺失图层。

`web/pin-houses.js` 是当前无纹理设计所需的精简 GLB reader，支持紧密排列 accessor、索引三角面、节点矩阵/变换和纯色 PBR。拒绝 sparse、交错 byteStride、非本地 buffer 和非三角模式；不是完整 GLTFLoader，不承诺纹理、压缩或任意模型兼容。实例共享克隆几何/材质，保持 Z-up，不做 Y-up 旋转。

### 6.4 照片层与操作

`web/photos.js` / `web/photos.css` 使用黄色编号 sprite、连接线、Raycaster 鼠标选取、悬停 tooltip、照片 dialog 和列表。点击照片只查看原场景中的叠加资料，不在 STL/3MF 增加标记。底层高程采用 DEM，标记视图抬升用于清晰可见。照片的时间与另一场徒步声明必须保留。

默认透视、北向上俯视、自动旋转、网格按钮沿用当前实现。`window.modelStatus` 与 `window.featureStatus` 提供调试快照；其中 modelStatus 的顶点/三角面来自打印 metadata，不应作为网页地形缓冲长度使用。

## 7. 导出与校验

### 7.1 打印文件

STL 是合并后的单一封闭实体，不存颜色或标准单位声明；导入切片器按 mm。3MF 使用核心格式 basematerials，每个三角面通过 pid / p1 / p2 / p3 对应材料，坐标按 mm 声明并写至小数点后 5 位。默认 9 种材质，禁用类别时只保留实际使用的材料资源；不是多耗材机器的专用工程或 G-code。

最终布尔后网格与可切换网页地形拓扑不同。STL/3MF 几何等价不意味着 STL 能保存分类色；网页与打印房屋使用同一原点与设计。

### 7.2 当前验证结果与口径

| 检查 | 当前结果 | 验证依据 |
| --- | --- | --- |
| STL 回读 | 封闭、绕序一致、单组件 | trimesh 回读并 split |
| 3MF 回读 | 封闭、绕序一致、单组件，外包尺寸匹配 | 解析 XML 顶点/三角形重新成网格，材料索引范围有效 |
| 平底 | z=0 | 构建前底部顶点断言，合并体最低点保持 0 |
| Manifold | `Error.NoError` | STL 回读转换为 manifold；不是只检查导出前对象 |
| 拓扑 | genus=1、单实体 | 允许贯通孔道，封闭实体不等于球拓扑 |
| 路线断口 | 圈内无路线抬升、无红色 | 顶点高程与地表相等，面 gap 不使用路线 ID |
| 圈外路线 | 核心净高约 0.8 mm | 高于原始地形与地表较高者 |
| 房屋连接 | 每栋与地形交集体积 >0，最终一个正体积组件 | 放置时求交与合并后分解 |
| 房屋不压路线 | 所有实际边缘净距 >0 | 完整 XY 投影与凸起/红色面距离，见第 4.8 节 |
| 湖泊水平 | 路线外水平高差为 0 | 湖面样点检查；不把穿越路线判作水面 |
| 网页规则 | 32 个地形开关组合检查通过 | `work/pin-ui-validation.json`，DOM 与 Three.js 几何，非浏览器截图 |

当前 DOM 重合成与默认二进制高度的最大差为 0.00000762939453125 mm。`work/pin-houses-off/` 与 `work/pin-uncertain/` 保存过关闭房屋、包含 uncertain 的成功导出；当前构建只读取这些既有记录设置摘要，不自动用 4 mm 配置重新构建全部对照组合。不能将它们宣传为本次所有打印组合均已重新回归。旧 `work/combination-check/` 高度场房屋全组合记录被标为 historical_only。

`browser_validation.status=not_run` 是当前默认导出记录的事实。用户此前确认过外部 Chrome 正常渲染，现有截图可作历史效果材料，但本次没有代理内浏览器验收或新截图。也没有切片/机器 G-code/真实打印；实体体积不是填充后耗材估计。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

这只是依赖环境安装，不自动获取缺失的 DEM/WorldCover 原始瓦片，也不自动准备照片源路径。


`verify_preview.command` 调用 `work/browser-test/verify.cjs`，依赖本机专用 Chrome headless shell 路径和运行中的预览服务。该脚本仍硬编码“六个图例”的旧断言；当前默认有九种打印材质及照片图例，因此**不能直接作为当前合格验收脚本**，需要先更新预期与房屋检查。它还会截图并改写元数据。当前沙箱有浏览器 Mach IPC 限制，截图由外部执行，不应以 DOM 测试冒充 WebGL 渲染测试。

## 11. 已知问题与改进方向

- 通用性：轨迹仅当前 gx:Track、固定区域 DEM 与照片路径，缺少清晰的数据下载/区域选取接口；建议分离数据准备、几何与导出参数。
- 质量：缺少切片与试打，图钉尺度小，斜坡嵌入、细节厚度及连接强度需实证；保持当前行为不等于这些问题已解决。
- 放置：采用摄影者坐标且不去重，不推断视线偏移；可增加人工编辑坐标及“拍摄点/建筑点”语义。
- 几何：现在填充负体积小空腔，但仍有 genus=1 通道；后续应把连接、内部空腔与打印支撑分别诊断，不能只看 watertight。
- 算法：路线用点加密近似距、不同 Track 段按顺序连续；可升级段索引、显式断段与可审计的网格截线。
- 数据：时间不一致、OSM 缺漏、DSM 含植被建筑表面、WorldCover 分类误差均可能影响效果；不以程序纹理补作测绘精度。
- 性能：测量批量布尔、GLB 实例与非索引地形内存；再评估 LOD、增量配色、局部更新与实例化，当前没有相关基准结论。
- 配置债务：清理 `preview_color`、全零 house_top/houses.bin、写死设计半宽和未迁移的 schema；支持配置路径不等于任意新 GLB 兼容。
- 验收追踪：给配置、原数据、生成缓冲、截图和检查记录绑定同一构建 ID/哈希；当前旧对照记录被主构建摘要引用，需要防止过期结果造成误读。
- 文档债务：README 同时保留多轮历史，旧“三角网格完全相同”“七色棕屋”等描述已不适用于当前；本方案只把现状写清，没有顺带重写历史文件。


## 12. 单侧海拔刻度实现与验收

海拔刻度数据源现已改为主轨迹 `data/route.kml`（2026-09-17）首尾点记录海拔，**不是 DEM 全范围最低/最高，也不是轨迹全程最低/最高**。实际起点 2009.541496 m、终点 3064.796875 m；全程记录最低 2006.294914 m、最高 3080.896367 m，仅保存作参考，不用于本组刻度。

按首尾记录海拔等分三个区间、产生四条线。数字取整到米，几何高程使用未取整值，映射仍以模型 DEM 的最低海拔为零基准：

```text
alt_i = route_start_alt + i * (route_end_alt - route_start_alt) / intervals
z_i = base_mm + (alt_i - dem_min) * (1000 / horizontal_scale) * vertical_exaggeration
```

因此第一条不是简单放在底座 4 mm 上，也不会把起点记录海拔改成 DEM 采样的起点海拔；它表示 GPS 记录海拔在模型高程体系中的位置。

| 显示文字 | 真实记录/插值海拔 m | 模型 Z mm | 放置 |
| --- | --- | --- | --- |
| S 2010 m | 2009.541496 | 4.977939 | 原位，无下移 |
| 2361 m | 2361.293289 | 14.140910 | 原位，无下移 |
| 2713 m | 2713.045082 | 23.303881 | 原位，无下移 |
| E 3065 m | 3064.796875 | 32.466852 | 原位，无下移 |

全部原位显示，不存在 `4737 m*`，当前网页也没有星号/下移提示。`S` 表示起点、`E` 表示终点，避免毫米尺度中文笔画的打印风险；S/E 与数字同样采用 4.5 mm 高、0.6 mm 笔画的实体字。字母 m 是单位符号，首尾标记不会被误解成另两种海拔来源。

刻度仍只在**南侧壁**：默认视角可见、侧壁面积约 9109.651 mm²，为四面最大。刻线长 7.0 mm、宽 0.6 mm，深灰 `#39434B`，浅浮雕向外凸出 0.35 mm，向实体内搭接 0.15 mm。文字和线条在局部坐标生成后与侧壁限高薄层求交，并与地形、房屋布尔合并。字高/笔画/侧面/颜色、房屋与断口等其余参数不变。当前四项不需要截短或移位。

### 配置与切换

`config/features.json` 新增 `elevation_scale.source`，默认 `route_start_end`；`terrain_min_max` 保留 DEM 范围刻度能力，只有显式选择时才使用旧的 DEM 极值模式。该模式仍可能需要下移最高项，网页会按实际 relocated 状态显示说明，不会把旧提示无条件显示到首尾模式。

| 字段 | 当前值 | 含义 |
| --- | --- | --- |
| `elevation_scale.enabled` | true | 启用打印刻度与网页刻度层 |
| `elevation_scale.source` | `route_start_end` | 可选 `route_start_end` / `terrain_min_max`；缺省补为首尾模式 |
| `elevation_scale.side` | `south` | 支持 south / north / east / west，当前南侧 |

执行 `.venv/bin/python build_model.py` 重建；`.venv/bin/python build_model.py --disable elevation_scale` 移除打印刻度。网页“海拔刻度”按钮只切换显示，不能改写已下载打印文件。`elevation_scale.py` 生成独立的网页浮雕缓冲 `web/layers/elevation_scale_vertices.bin`（Float32 XYZ）与 `web/layers/elevation_scale_faces.bin`（Uint32 索引），原地形缓冲不改动。

### 元数据、校验与本次迭代

## 13. 上传与流水线架构

本地上传应用入口 `/`，示例作品 `/web/`。`server.py` 使用标准库 `ThreadingHTTPServer`，默认绑定 `127.0.0.1:8765`；上传页与预览页均为静态 HTML/JS，无前端打包步骤。同一端口仅运行一个监听进程。

### 启动与端口

```sh
# 在 huan-path 根目录
.venv/bin/python server.py
# 或指定端口
.venv/bin/python server.py --port 8766
```

`start_preview.command`：若本机已有健康的应用服务则直接打开上传入口；否则启动默认 8765。脚本只识别本应用健康检查，不向未知进程发终止信号。端到端验收记录见 `work/upload-e2e-results.json`（当时临时使用 8766）。

### 用户流程与界面

1. 上传 KML 或 KMZ，创建 `jobs/<job_id>/`，原始上传写为 input.kml / input.kmz，源文件不修改或移动。
2. 请求立即返回任务 ID；最多两个任务并行处理，其余排队。页面每秒轮询，显示八阶段状态、说明和实际耗时。
3. 失败会保留阶段、原因、构建日志和重试入口；重新运行保留可人工修改的房屋判断表。中断的任务可重试。
4. 成功后自动进入该任务的三维预览。标题、日期、起终点名、记录里程来自上传文件；尺寸、比例、高度夸张来自本次模型，未将新任务写成雨崩示例。
5. 保留六个模型元素按钮（河流/湖泊、林区、草地、冰雪、房屋、海拔刻度）、独立照片开关/列表、透视/北向上/自动旋转/网格及 STL/3MF 下载。
6. 署名与许可集中在右侧面板底部默认收起的「数据来源」（OSM ODbL、ESA WorldCover CC BY 4.0、Copernicus）。右下图例保留。来源问题与建筑判断路径在「生成说明」中展示。
7. 照片任务可用「编辑房屋判断」修改 true / false / uncertain 及理由，保存后重建；图钉仍锚定拍摄点坐标。

### 自动数据与地理参数

上传解析位于 `app/tracks.py`，支持 gx:Track 或 LineString，提取 Document 名称、BeginTime/when 日期、PosStartName/PosEndName、Distance/Mileage、照片 FileId 等。当前两步路多段 Track 仍按导出顺序连接，记录潜在停录连接线警告。

UTM 由轨迹中心经纬度自动选择分区和南北半球；输入为 WGS84。范围由轨迹包围框加四周 1,100 m；最长边映射到全局打印目标 200 mm。DEM 由范围选择 1° Copernicus 瓦片，WorldCover 选择 3° 分幅，支持跨瓦片拼接裁剪；UTM 分区与瓦片编号由本次轨迹计算。默认高度夸张按 `clip(72 / (DEM高差 × mm_per_m), 1, 2)` 自动计算，必要时增厚底座以容纳低于 DSM 最低值的轨迹记录海拔。200 mm、1,100 m、72 mm 为产品打印画幅 / 留边 / 目标起伏策略。

任务 DEM 与 WorldCover 先按原始栅格裁剪，主构建器再按任务 CRS 重投影到模型网格。单个原始瓦片缓存于 `cache/`，裁剪、OSM 原始响应/查询/许可、照片原件与判断表全部写入任务的 `data/`。输入无高程时明确使用 DEM 回填首尾，不伪称 GPS 海拔。示例 CLI 不带 `--job-spec` 时保留原投影、比例与 1.25× 高度夸张。

### 八阶段及实现边界

| 阶段 | 实际工作 |
| --- | --- |
| 解析轨迹 | 安全读取 KML/KMZ，轨迹坐标/元信息/照片附件索引，计算投影与范围 |
| 获取地形数据 | 选择 DEM 瓦片，下载或验证真实缓存，按本次范围裁剪 |
| 3D 地形建模 | DEM 投影网格、自动比例/高程夸张、路线加密和距离场 |
| 河流与地表要素 | 获取 OSM / WorldCover，生成水体、林区、草地、雪冰掩膜及高程修改 |
| 照片点与房屋 | 提取 KMZ 原图、生成网页图，DEM 锚定，识别/推断建筑，生成房屋与路线断口 |
| 海拔刻度 | 按记录起终点海拔等分，生成选定侧壁的毫米级浮雕 |
| 导出与校验 | 地形/图钉/刻度布尔合并、STL/3MF 与共享缓冲写出、回读检查 |
| 网页预览 | 封装网页资产与照片数据、写最终元数据/通用下载链接，完成后发布任务 URL |

部分共享缓冲随导出写出，最后阶段负责封装和可访问发布，不将此前耗时算成浏览器渲染时间。

### 可插拔房屋判断

配置环境变量 `OPENAI_API_KEY` 后，使用 Responses API 对任务派生 JPEG 逐张判断建筑，结构化输出 has_house / reason。密钥仅通过进程环境注入（`export OPENAI_API_KEY=...`）；模型名可用 `OPENAI_VISION_MODEL` 覆盖，默认 `gpt-4.1-mini`。请求体仅含待识别照片；浏览器不持有密钥。UI 说明照片外发与潜在费用。合同见官方文档：<https://developers.openai.com/api/docs/guides/images-vision>；结构化输出与图片请求经 mock 测试。端到端实测时未配置 key，房屋走 `osm_nearby`。

未配置 key 则走 `osm_nearby`：在照片拍摄点附近 **75 m** 内查 OSM building，记录最近距离和对象 ID。该判断仅说明附近有无已绘制建筑，不说明照片中是否看到了它；OSM 漏绘仍可能导致 false。查数失败则标 uncertain，默认不放屋。请求失败与模型错误不伪装成 false。

两条路径均写 `jobs/<job_id>/data/photo_houses.json`（坐标、来源、理由、判断）。页面可改；重试优先保留现有表。人工修正后 method/source 为 `manual`。无照片时走 `no_photos`，预览层按任务实际资源显示。

### 校验、隔离与已知限制

- 雨崩示例原 STL/3MF 未覆盖。`work/example-regression-check.json` 记录：独立回归的 STL 字节一致，3MF 各 XML 内容一致（ZIP 时间戳可不同），默认打印文件哈希保持原样。
- `tests/test_inputs.py` 验证南半球 UTM、跨瓦片选择、KMZ/LineString、缺失高程和恶意 DTD 拒绝；`tests/test_vision.py` 验证视觉接口请求与返回合同，共七个单元测试通过（另含起终点海拔相同的刻度避让测试）。
- `tests/http_checks.py` 验证即时接收、失败/重试、房屋人工修正、跨域 Origin 限制和文件路径隔离；`tests/job-ui.mjs` 验证两任务动态标题/日期/下载、署名折叠、六类开关、刻度及 28 张照片标记/列表/弹窗/判断编辑器。
- `work/upload-page-validation.json` 验证上传页文件名编码、八阶段、成功自动跳转及失败重试入口；`work/upload-ui-validation.json` 为 DOM / Three.js 检查，不是 WebGL 浏览器截图。代理内未启动浏览器，截图仍由外部完成。
- 当前限制：上传 150 MB，KMZ 原始解压累计 800 MB、文件 2,500 个，KML 50 MB，轨迹最多 200,000 点、模型跨度 200 km、每任务照片最多 150 点。超限明确失败；不支持跨日期变更线或 UTM 极地范围，海区缺失 DEM 会失败，不伪造地形。
- 支持一般区域的自动选择不等于已在全球多区域实测；新区域冷下载、视觉真实账号、设备切片与实物打印仍未验收。失败的外部类别可降级并记明来源；DEM 缺失属于致命错误。
- 模型输入的日期/里程/记录海拔可能有误差，建筑推断与摄影点不是真实建筑测绘；现有陡坡嵌入、图钉尺度与打印兼容性限制继续适用。
- 本地服务绑定 loopback，校验 Host/Origin；发布范围限于应用 UI、任务 `web/` / `models/` 及白名单后缀静态资源。

## 15. 道路图层

道路属于「河流与地表要素」阶段的预览子步骤。`app/roads.py` 负责获取、分级、投影裁剪与细带缓冲；模型矩形四角反投影确定 WGS84 查询 bbox。打印几何由原有高度场流水线生成，道路以独立网页缓冲展示。

### 数据来源与缓存

`app/datasets.py` 为共用 curl 下载器解析代理，优先级为 `config/features.json` 的 `network.proxy`、HTTPS_PROXY / https_proxy / ALL_PROXY / all_proxy、macOS 系统代理、直连。配置 `null` 使用自动选择，`"off"` 使用直连；本机回环请求直接连接。来源记录保存代理来源与主机名，代理经 curl `-K -` stdin 配置传入，转义引号、反斜杠及换行；argv 无代理串。失败仅记录 HTTP 状态或 curl 退出码，超时不保留命令异常文本。网络配置不进入作品有效配置与网页 metadata。

道路依次请求 kumi、private.coffee、mail.ru、overpass-api.de，查询保持 `way["highway"] ... out body geom`。连接超时 10 秒；Overpass 单源至多 45 秒，按剩余预算为后续源分配时间，并预留主 API 时间。道路网络预算 149 秒，主 API 每块至多 30 秒。耗尽预算时记录警告、输出空道路并继续任务。

镜像失败后请求 `https://api.openstreetmap.org/api/0.6/map.json?bbox=...`。面积超过 0.25 deg²，或响应 HTTP 400 时沿较长边二分，递归上限 12 层；509 按普通失败处理；各块受同一预算约束。合并节点表与 way ID，筛选 highway，与导入解析共用 `way_geometry` 拼接 geometry，缺节点的不完整 way 直接跳过，统一为 Overpass 风格 `{elements:[{type:'way',id,tags,geometry:[{lat,lon}]}]}`。

缓存沿用 `cache/osm-<查询 SHA256 前24位>.json`，查询和七位小数 bbox 组成原有键；旁置 `.source.json` 保存 endpoint、source_type、proxy、previous_errors 与覆盖范围。每个请求使用独立临时文件，验证完整响应后原子写入；并发失败请求保留其他任务的有效缓存。任务保存 `data/osm_roads_raw.json` / `osm_roads_source.json`，包含署名和可用状态。

### 本地导入与 UI 状态

上传页可附加最大 50 MB 的 OSM JSON、OSM XML（.osm / .xml）或 GeoJSON。JSON 支持 geometry 及 way nodes + node 表；XML 支持 node / nd 引用及 nd 坐标；GeoJSON 支持 LineString / MultiLineString，properties.highway 缺省为 path。先去 UTF-8 BOM；用 bytes 正则检查 DTD/ENTITY，避免整体大写复制。解析、坐标、DTD/ENTITY、文件大小与区域相交检查在服务端执行，错误以明确文案返回。

新作品使用 `POST /api/jobs?...&defer=1` 保存轨迹，再通过 `POST /api/jobs/<id>/roads?filename=...` 导入，最后由 retry 启动流水线。原文件保存在作品 `data/roads-upload.<扩展名>`，标准化文件为 `roads_import.json`，来源为 `roads_import_source.json`。作品本地文件优先于在线与共享缓存，导入不写共享缓存；读取时忽略旧版来源为 local 的共享缓存。道路 POST 失败时显示原因及稍后导入提示，仍调用 retry 启动构建并选择作品。

已有作品的「导入道路文件」按钮调用同一接口，仅重建道路缓冲和 metadata / validation 中的道路记录，并调用流水线 `package_preview` 同步整套网页脚本、样式与 vendor。地形比例、打印文件与其他图层保持原有成果。接口复用 Host / Origin 校验与任务运行互斥。

工作台、直达预览与 `?huanApp=1` / `embedded=1` 共用前端。有道路显示本地文件名或 OSM endpoint 主机名；空道路禁用开关，并区分「道路获取失败」与「该区域无道路」，同时显示导入入口。页面使用空 data favicon，服务对 favicon.ico 返回 204。
